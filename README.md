# trade-journal

Дневник трейдера: сделки с Bybit, обоснование входа, статистика. Локально на macOS,
без бэкенда и без облака.

**Статус: ворота сверки пройдены** — все закрытые сделки за 90 дней сошлись с
`closed-pnl` Bybit посделочно, ноль расхождений. Работают: бэкфилл, склейка сделок,
журнал, статистика, локальный дашборд, Telegram-бот и Mini App.

> [!IMPORTANT]
> **Это личный инструмент, выложенный как есть.** Поддержки, дорожной карты и
> обещаний совместимости нет. Issues могут остаться без ответа, PR — тоже.
> Форкайте свободно: лицензия MIT.
>
> Работает **только с Bybit, только с USDT-перпетуалами** (`category=linear`).
> Спот сознательно не поддержан: у него нет `closed-pnl`, а значит нечем
> независимо проверить склейку исполнений в сделки. Принцип проекта — не строить
> то, что нельзя проверить.
>
> Прежде чем доверять цифрам, прогоните `reconcile` на своей истории. Совпадение
> у автора не гарантирует совпадения у вас: режимы маржи, хедж и валюта комиссии
> у всех разные.

## Безопасность

Ключ биржи должен быть **только на чтение**. Программа проверяет это при каждом
запуске и отказывается работать с ключом, у которого есть право торговать.

Если вы запускали проект с ключом, дающим больше прав, — отзовите его: Bybit →
API → удалить ключ, затем выпустить новый с переключателем Read-Only. Понизить
права у созданного ключа нельзя, только пересоздать.

Ключи хранятся в Keychain (macOS) или в переменных окружения (Linux) и никогда
не пишутся в файлы репозитория. База с историей сделок лежит вне репозитория и
закрыта `.gitignore`.

## Принципы

- **Никакого бэкенда.** Данные и ключи не покидают машину.
- **Ключ только на чтение**, только в Keychain. Проверяется программно при каждом запуске:
  ключ с правом торговать или выводить будет отвергнут.
- **Ноль внешних зависимостей.** Только стандартная библиотека Python — нечему
  утечь через цепочку поставок.
- **Сырые fills неизменяемы.** Всё производное пересчитывается из них, поэтому
  исправление логики не требует повторной выкачки истории.
- **Цифры сверяются с биржей посделочно.** Пока не сходятся — UI не строится.

## Установка ключа

Создай на Bybit API-ключ **только с правами на чтение** и положи в Keychain:

```sh
security add-generic-password -s trade-journal -a bybit-key    -w
security add-generic-password -s trade-journal -a bybit-secret -w
```

Пароль вводится интерактивно и не попадает в историю шелла.

## Использование

### Данные с биржи

```sh
python3 -m journal.cli check-key              # ключ действительно только на чтение?
python3 -m journal.cli backfill --days 90     # выкачать fills (окнами по 7 дней)
python3 -m journal.cli rebuild                # собрать сделки и привязать намерения
python3 -m journal.cli reconcile --days 90    # ВОРОТА: сверка с closed-pnl биржи
```

`reconcile` возвращает ненулевой код выхода, пока хоть одна сделка расходится больше
чем на 1%.

### Журнал

```sh
# ДО входа - в этом весь смысл, потом будет поздно
python3 -m journal.cli intent BTCUSDT long "пробой недельного уровня" \
        --stop 95 --signal "объём на пробое" --tags breakout

python3 -m journal.cli pending                # закрытые сделки без обоснования
python3 -m journal.cli note <trade_id> "вышел рано, испугался фитиля"
python3 -m journal.cli coverage --days 30     # сколько сделок осталось без разбора
```

### Приложение на маке

```sh
python3 -m journal.cli app              # http://127.0.0.1:8321
```

Дневник и синхронизация в одном процессе: интерфейс поднят всегда, а раз в
минуту фоновый поток забирает с биржи новые fills и обменивается журналом с
сервером. В автозапуск ставится LaunchAgent'ом (см. `deploy/README.md`),
в Dock — через «Добавить в Dock» в Safari.

Тёмный дашборд: KPI с интервалами, топ прибыльных сделок, свои правила
торговли и список сделок с разбором прямо в строке (клик по сделке →
«почему заходил» плюс какие правила нарушены → сохранить). Заголовочная
метрика — разобранность, как решено в grilling-сессии. Сервер слушает только
127.0.0.1, написан на stdlib и не делает ни одного внешнего запроса —
шрифты системные, CSP `default-src 'none'`.

Только интерфейс, без обновления данных — `app --no-sync`. Голый сервер без
синхронизации — `serve`; им же поднимается Mini App на сервере.

### Правила торговли

Правила пишутся руками в панели «Правила», а при разборе сделки отмечается,
какие из них нарушены. Дальше дневник считает разницу: сколько дают сделки с
нарушением и сколько — без.

Три вещи в этом счёте сделаны намеренно:

- сравниваются **только разобранные** сделки. У неразобранной галочки не
  проставлены не потому, что правила соблюдены, а потому, что её никто не
  смотрел; попав в «чистые», она задрала бы их результат;
- пока хоть в одной из двух групп меньше 30 сделок, рядом написано, что
  разница ничего не доказывает. Иначе «правило, которое стоит мне денег»
  находится всегда — оно ищется в шуме;
- убранное правило уходит в архив, а не удаляется: на него ссылаются разборы
  прошлых сделок.

### Telegram Mini App (дашборд на телефоне)

Дашборд открывается внутри Telegram кнопкой в боте. Требует **публичного HTTPS**
(Telegram не принимает самоподписанные сертификаты), поэтому живёт на сервере,
а не на 127.0.0.1:

```sh
python3 -m journal.cli serve --miniapp --host 127.0.0.1 --port 8321
```

Перед HTTPS-прокси (Caddy/nginx). Каждый вызов API обязан предъявить подпись
Telegram `initData`: проверяется HMAC, свежесть и то, что пользователь -
владелец. Без подписи API отвечает 401, а страница не содержит данных.

### Обмен данными между маком и сервером

Ключи биржи остаются на маке, поэтому сделки едут только в одну сторону:
мак → сервер. **Журнал ездит в обе стороны** — разбор пишется и в дневнике на
маке, и с телефона, поэтому при слиянии побеждает более свежая правка, а не
сторона. `trade_id` детерминирован, так что разборы остаются привязанными
после любой пересборки.

Обычно это делает `deploy/sync.sh` (его же раз в минуту запускает приложение).
Руками — тот же круг по шагам:

```sh
# на маке: сделки и журнал на сервер
python3 -m journal.cli export /tmp/transfer.db
scp /tmp/transfer.db server:/tmp/

# на сервере
python3 -m journal.cli import /tmp/transfer.db

# обратно: журнал с сервера на мак
python3 -m journal.cli export /tmp/journal.db --journal-only
```

Повторная заливка идемпотентна: таблицы сделок append-only с ключами от биржи.

Из двусторонности следует правило, которое нельзя нарушать: **в журнале ничего
не удаляется физически**. Стёртый разбор — пустое тело, снятое нарушение —
`broken=0`, убранное правило — `active=0`. Удалённая строка вернулась бы с
другой стороны первым же кругом, и удаление выглядело бы как призрак.

Цена решения: «побеждает свежее» опирается на согласованные часы мака и
сервера. Оба под NTP, и одну заметку не правят с двух устройств одновременно,
поэтому расхождение в секунды роли не играет.

### Telegram-бот (журнал с телефона)

Разовая настройка: получить токен у [@BotFather](https://t.me/BotFather), узнать свой
chat_id у [@userinfobot](https://t.me/userinfobot), положить оба в Keychain:

```sh
security add-generic-password -U -s trade-journal -a telegram-token -w
security add-generic-password -U -s trade-journal -a telegram-chat-id -w
```

```sh
python3 -m journal.cli bot
```

Команды: `/stats [3d|7d|30d]`, `/trades [период]`, `/pending`, `/help`.

Разбор пишется **ответом** на сообщение из `/pending` - на телефоне это разница
между «сделаю» и «не буду». Бот отвечает только своему chat_id, чужие сообщения
игнорирует молча (ответ «доступ запрещён» подтвердил бы, что бот существует),
ключей биржи не касается и читает только SQLite.

Баланс, депозит и открытые позиции не отдаются ни одной командой - и не потому,
что так решено, а потому что в базе их нет: хранятся закрытые сделки.
Помни при этом, что всё отправленное проходит через серверы Telegram.

### Статистика

```sh
python3 -m journal.cli stats                  # за всю историю
python3 -m journal.cli stats --days 30
```

Отчёт устроен так, чтобы из него нельзя было вынести вывод, который данные не
поддерживают: каждое число идёт с размером выборки, доли — с интервалом Уилсона,
матожидание — с бутстрап-интервалом, срез по символу скрывается при n<30, а
R-multiple помечается недоступным, если стоп не был записан до входа.

Намерение привязывается к сделке автоматически при `rebuild`: тот же символ и
направление, вход в пределах 24 часов после записи. Обоснование, написанное **после**
входа, не привяжется никогда - иначе поле «обоснование до входа» ничего не значило бы.

Без планового стопа R-multiple по сделке не считается. Это не строгость ради строгости:
стоп, восстановленный по памяти, превратил бы всю R-статистику в фикцию.

```sh
python3 -m unittest discover -s tests -t .
```

Не требуют ключей и сети.

## Что здесь считается «сделкой»

См. [docs/trade-definition.md](docs/trade-definition.md) — это контракт, код следует ему.
Спор о цифрах решается сначала там, потом в коде.

## Ограничения, которые стоит знать заранее

- Только `linear` (USDT-перпетуалы). Спот исключён: для него у Bybit нет `closed-pnl`,
  то есть нечем проверить склейку.
- Глубина истории — 2 года, окнами запроса по 7 дней.
- Автоимпорт работает **вперёд**: восстановить давнюю историю подробнее, чем отдаёт API,
  невозможно.
