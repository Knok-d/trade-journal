# trade-journal

Дневник трейдера: сделки с Bybit, обоснование входа, статистика. Приложение на
macOS; чужого облака нет, ключи биржи не покидают мак.

**Статус: ворота сверки пройдены** — все закрытые сделки сошлись с `closed-pnl`
Bybit посделочно, ноль расхождений. Работают: бэкфилл, склейка сделок, журнал с
правилами и основаниями, статистика, графики, приложение для мака,
Telegram-бот и Mini App.

Доступ с телефона — опциональный: под него поднимается **свой** маленький
сервер (`deploy/README.md`), на который уезжают посчитанные сделки. Ключи биржи
туда не едут никогда; без телефона сервер не нужен вовсе.

> [!IMPORTANT]
> **Это личный инструмент, выложенный как есть.** Поддержки, дорожной карты и
> обещаний совместимости нет. Issues могут остаться без ответа, PR — тоже.
> Форкайте свободно: лицензия MIT.
>
> Работает **только с Bybit, только с USDT-перпетуалами** (`category=linear`).
> Спот сознательно не поддержан: у него нет `closed-pnl`, а значит нечем
> независимо проверить склейку исполнений в сделки. Принцип проекта — не строить
> то, что нельзя проверить.
>
> Прежде чем доверять цифрам, прогоните `reconcile` на своей истории. Совпадение
> у автора не гарантирует совпадения у вас: режимы маржи, хедж и валюта комиссии
> у всех разные.

## Безопасность

Ключ биржи должен быть **только на чтение**. Программа проверяет это при каждом
запуске и отказывается работать с ключом, у которого есть право торговать.

Если вы запускали проект с ключом, дающим больше прав, — отзовите его: Bybit →
API → удалить ключ, затем выпустить новый с переключателем Read-Only. Понизить
права у созданного ключа нельзя, только пересоздать.

Ключи хранятся в Keychain (macOS) или в переменных окружения (Linux) и никогда
не пишутся в файлы репозитория. База с историей сделок лежит вне репозитория и
закрыта `.gitignore`.

## Принципы

- **Ключи не покидают мак.** Чужого облака в проекте нет. Если включить доступ
  с телефона, сделки уедут на ваш собственный сервер — но ключи биржи остаются
  на маке, и на бирже за них ходит только он.
- **Ключ только на чтение**, только в Keychain. Проверяется программно при каждом запуске:
  ключ с правом торговать или выводить будет отвергнут.
- **Ноль внешних зависимостей.** Только стандартная библиотека Python — нечему
  утечь через цепочку поставок.
- **Сырые fills неизменяемы.** Всё производное пересчитывается из них, поэтому
  исправление логики не требует повторной выкачки истории.
- **Цифры сверяются с биржей посделочно.** Пока не сходятся — UI не строится.

## Установка ключа

Создай на Bybit API-ключ **только с правами на чтение** и положи в Keychain:

```sh
security add-generic-password -s trade-journal -a bybit-key    -w
security add-generic-password -s trade-journal -a bybit-secret -w
```

Пароль вводится интерактивно и не попадает в историю шелла.

## Использование

### Данные с биржи

```sh
python3 -m journal.cli check-key              # ключ действительно только на чтение?
python3 -m journal.cli backfill --days 90     # выкачать fills (окнами по 7 дней)
python3 -m journal.cli rebuild                # собрать сделки и привязать намерения
python3 -m journal.cli reconcile --days 90    # ВОРОТА: сверка с closed-pnl биржи
```

`reconcile` возвращает ненулевой код выхода, пока хоть одна сделка расходится больше
чем на 1%.

### Журнал

```sh
# ДО входа - в этом весь смысл, потом будет поздно
python3 -m journal.cli intent BTCUSDT long "пробой недельного уровня" \
        --stop 95 --signal "объём на пробое" --tags breakout

python3 -m journal.cli pending                # закрытые сделки без обоснования
python3 -m journal.cli note <trade_id> "вышел рано, испугался фитиля"
python3 -m journal.cli coverage --days 30     # сколько сделок осталось без разбора
```

### Сделки с MT5 (Bybit TradFi CFD)

Счёт MetaTrader 5 через API Bybit не отдаётся, поэтому строки берутся из таблицы
истории веб-трейдера: выдели их, скопируй, положи в файл — одна сделка на строку,
колонки в том же порядке, разделитель табуляция.

```sh
python3 -m journal.cli mt5-import сделки.tsv           # показать, что понято
python3 -m journal.cli mt5-import сделки.tsv --write   # записать
```

Импорт проверяет ввод двумя способами, потому что сверить эти сделки не с чем:
тождеством `общий P&L = P&L ордера + обмен − комиссия` и размером контракта,
выведенным из каждой строки, — у одного инструмента он обязан быть один. На
реальных данных он равен 1 у акций и индекса и 10 у палладия, так что
самодельный расчёт P&L завысил бы палладий вдесятеро. Именно поэтому цифры
берутся у брокера готовыми, а не вычисляются.

Повторный ввод той же строки исправляет опечатку, а не задваивает сделку: ключ —
ID позиции от брокера. Разбор при этом остаётся на месте.

### Приложение на маке

```sh
python3 -m journal.cli app              # http://127.0.0.1:8321
```

Дневник и синхронизация в одном процессе: интерфейс поднят всегда, а раз в
минуту фоновый поток забирает с биржи новые fills и обменивается журналом с
сервером. В автозапуск ставится LaunchAgent'ом (см. `deploy/README.md`).

Оболочка для Dock собирается своя — `mac/build.sh --install` кладёт
`Trade Journal.app` в `/Applications`: окно с `WKWebView`, своё меню, иконка,
нарисованная кодом. Нужны только `swiftc` и `iconutil` из Command Line Tools,
Xcode не требуется.

Тёмный дашборд: кривая эквити и результат по дням сверху, KPI с интервалами,
топ прибыльных сделок, свои правила и основания входа, список сделок с разбором
прямо в строке (клик по сделке → «почему заходил», на чём заходил, какие правила
нарушил → сохранить). Сервер слушает только 127.0.0.1, написан на stdlib и не делает
ни одного внешнего запроса — шрифты системные, CSP `default-src 'none'`,
графики нарисованы руками в SVG без единой библиотеки.

Только интерфейс, без обновления данных — `app --no-sync`. Голый сервер без
синхронизации — `serve`; им же поднимается Mini App на сервере.

### Правила и основания входа

Два своих списка коротких формулировок: **правила**, которые нарушают
(«не усредняться в убыток»), и **основания**, на которых заходят («отскок от
уровня», «сигнал»). При разборе сделки и то и другое отмечается галочками —
основания заодно избавляют от необходимости печатать одно и то же руками.

Механика у обоих одна, поэтому и считается одинаково: дневник показывает
разницу между сделками с отметкой и без неё.

**Проставленного основания достаточно, чтобы сделка считалась разобранной** —
абзац текста сверх него не обязателен. Отметил, на чём заходил, значит на
сделку посмотрел; требовать большего значило бы показывать разобранность ниже
настоящей. Само нарушение правила разбором при этом не считается: иначе группа
«нарушившие» пополнялась бы сделками, где галочку поставили, ни во что больше
не глядя, и сравнивать группы стало бы нельзя.

Три вещи в этом счёте сделаны намеренно:

- сравниваются **только разобранные** сделки. У неразобранной галочки не
  проставлены не потому, что правила соблюдены, а потому, что её никто не
  смотрел; попав в «чистые», она задрала бы их результат;
- пока хоть в одной из двух групп меньше 30 сделок, рядом написано, что
  разница ничего не доказывает. Иначе «правило, которое стоит мне денег»
  находится всегда — оно ищется в шуме;
- убранная строка уходит в архив, а не удаляется: на неё ссылаются разборы
  прошлых сделок.

### Что ещё показывает дневник

- **Кривая эквити и результат по дням** над цифрами. У кривой в подписи
  максимальная просадка — итог её не показывает: −900 в конце бывают и ровным
  сползанием, и качелями на полторы тысячи. Сутки режутся по местному времени,
  а не по UTC, иначе ночная сделка уезжает во вчера.
- **PnL % и плечо** на каждой сделке. Процент считается от маржи
  (`closedPnl ÷ (объём входа ÷ плечо)`) — это тот же ROI, что показывает Bybit,
  и его можно сверить с кабинетом. Где сделка с `closed-pnl` не сопоставилась,
  стоит прочерк, а не ноль.
- **Произвольный период**: пресеты 7/30/90/всё плюс свой отрезок. Пресет считается
  от последней сделки, отрезок — по календарю. Календарь свой, а не нативный
  `<input type="date">`: его выпадающую часть рисует браузер, стилизовать её
  нельзя в принципе, и на тёмной странице она выглядела чужой заплаткой.
- **Своя выборка в списке сделок**: поиск по тикеру (подстрокой), порядок по
  времени / по профиту / по убытку и отбор по отметке — клик по цифрам правила
  или основания оставляет в списке только те сделки. Всё это меняет **только
  список**: цифры и графики над ним остаются про весь период, иначе поиск по
  одному тикеру молча превращал бы сводку в отчёт по одной монете. Открытая
  позиция в сортировках по деньгам уходит вниз — итога у неё нет.
- **Крипта отдельно от TradFi.** Bybit торгует золотом, нефтью и акциями теми же
  USDT-перпетуалами (`XAUUSDT`, `CLUSDT`, `CRWVUSDT`), и в общей куче они
  неразличимы. Класс берётся у самой биржи — поле `symbolType` в
  `/v5/market/instruments-info`, — потому что на глаз он не читается: `HEIUSDT`
  выглядит как акция HEICO и является криптой, `MUUSDT` выглядит как токен и
  является Micron. Переключатель «крипта / TradFi» меняет разом сводку, графики
  и таблицу; окно периода при этом не сдвигается, иначе половины стали бы
  несравнимы.
- **Разбор можно писать на открытой позиции** — она стоит первой строкой в
  таблице и не прячется фильтром периода. Текст, написанный до того, как стал
  известен исход, помечен: «разобрана до закрытия». Метка гаснет сама, если
  текст правили после выхода — запрещать правку незачем, а выдавать поздний
  текст за ранний нельзя.
- **Открытые позиции** с нереализованным P&L, плечом и ценой ликвидации —
  цифрами самой биржи. Рядом обязательно возраст снимка: P&L, показанный как
  текущий, но снятый десять минут назад, — худшее, что может показать дневник.

### Telegram Mini App (дашборд на телефоне)

Дашборд открывается внутри Telegram кнопкой в боте. Требует **публичного HTTPS**
(Telegram не принимает самоподписанные сертификаты), поэтому живёт на сервере,
а не на 127.0.0.1:

```sh
python3 -m journal.cli serve --miniapp --host 127.0.0.1 --port 8321
```

Перед HTTPS-прокси (Caddy/nginx). Каждый вызов API обязан предъявить подпись
Telegram `initData`: проверяется HMAC, свежесть и то, что пользователь -
владелец. Без подписи API отвечает 401, а страница не содержит данных.

### Обмен данными между маком и сервером

Ключи биржи остаются на маке, поэтому сделки едут только в одну сторону:
мак → сервер. **Журнал ездит в обе стороны** — разбор пишется и в дневнике на
маке, и с телефона, поэтому при слиянии побеждает более свежая правка, а не
сторона. `trade_id` детерминирован, так что разборы остаются привязанными
после любой пересборки.

Обычно это делает `deploy/sync.sh` (его же раз в минуту запускает приложение).
Руками — тот же круг по шагам:

```sh
# на маке: сделки и журнал на сервер
python3 -m journal.cli export /tmp/transfer.db
scp /tmp/transfer.db server:/tmp/

# на сервере
python3 -m journal.cli import /tmp/transfer.db

# обратно: журнал с сервера на мак
python3 -m journal.cli export /tmp/journal.db --journal-only
```

Повторная заливка идемпотентна: таблицы сделок append-only с ключами от биржи.

Из двусторонности следует правило, которое нельзя нарушать: **в журнале ничего
не удаляется физически**. Стёртый разбор — пустое тело, снятое нарушение —
`broken=0`, убранное правило — `active=0`. Удалённая строка вернулась бы с
другой стороны первым же кругом, и удаление выглядело бы как призрак.

Цена решения: «побеждает свежее» опирается на согласованные часы мака и
сервера. Оба под NTP, и одну заметку не правят с двух устройств одновременно,
поэтому расхождение в секунды роли не играет.

### Telegram-бот (журнал с телефона)

Разовая настройка: получить токен у [@BotFather](https://t.me/BotFather), узнать свой
chat_id у [@userinfobot](https://t.me/userinfobot), положить оба в Keychain:

```sh
security add-generic-password -U -s trade-journal -a telegram-token -w
security add-generic-password -U -s trade-journal -a telegram-chat-id -w
```

```sh
python3 -m journal.cli bot
```

Команды: `/stats [3d|7d|30d]`, `/trades [период]`, `/pending`, `/help`.

Разбор пишется **ответом** на сообщение из `/pending` - на телефоне это разница
между «сделаю» и «не буду». Бот отвечает только своему chat_id, чужие сообщения
игнорирует молча (ответ «доступ запрещён» подтвердил бы, что бот существует),
ключей биржи не касается и читает только SQLite.

Баланс и депозит не отдаются ни одной командой — их в базе нет вовсе.

С открытыми позициями иначе, и об этом стоит знать точно. Раньше их не было в
базе, теперь есть: снимок висит в `open_positions` и показывается в Mini App —
объём, вход, плечо, нереализованный P&L и цена ликвидации. Команды бота их
по-прежнему не отдают, но уже **по решению**, а не потому, что данных нет.
Если такой обмен вам не нужен, не поднимайте сервер: без него снимок остаётся
на маке.

Помни при этом, что всё отправленное проходит через серверы Telegram.

### Статистика

```sh
python3 -m journal.cli stats                  # за всю историю
python3 -m journal.cli stats --days 30
```

Отчёт устроен так, чтобы из него нельзя было вынести вывод, который данные не
поддерживают: каждое число идёт с размером выборки, доли — с интервалом Уилсона,
матожидание — с бутстрап-интервалом, срез по символу скрывается при n<30, а
R-multiple помечается недоступным, если стоп не был записан до входа.

Намерение привязывается к сделке автоматически при `rebuild`: тот же символ и
направление, вход в пределах 24 часов после записи. Обоснование, написанное **после**
входа, не привяжется никогда - иначе поле «обоснование до входа» ничего не значило бы.

Без планового стопа R-multiple по сделке не считается. Это не строгость ради строгости:
стоп, восстановленный по памяти, превратил бы всю R-статистику в фикцию.

## Тесты

```sh
python3 -m unittest discover -s tests -t .
```

133 теста, ключей и сети не требуют.

Отдельно стоит знать про один из них: `tests/test_db.py` заводит таблицу в
**старой** форме и прогоняет по ней миграции. Так и должно быть — тесты на
свежей базе не ловят целый класс ошибок, потому что `ALTER TABLE` дописывает
колонку в конец, а не туда, где она объявлена в схеме. На этом однажды молча
разъехались три колонки у части исполнений.

## Что здесь считается «сделкой»

См. [docs/trade-definition.md](docs/trade-definition.md) — это контракт, код следует ему.
Спор о цифрах решается сначала там, потом в коде.

## Ограничения, которые стоит знать заранее

- Только `linear` (USDT-перпетуалы). Спот исключён: для него у Bybit нет `closed-pnl`,
  то есть нечем проверить склейку.
- **Сделки с MT5 не сверены и сверены быть не могут.** Перпетуалы на золото, нефть
  и акции живут на едином счёте и проходят полную сверку наравне с криптой. А
  TradFi CFD — отдельный счёт MetaTrader 5, которого API Bybit не отдаёт вовсе
  (`category` знает только `spot | linear | inverse | option`). Оттуда данные
  вносятся вручную (`mt5-import`), P&L берётся готовым от брокера, и второго
  источника для сравнения не существует. Такие сделки помечены в дневнике и
  выведены из отчёта сверки отдельной строкой — это «сравнить не с чем», а не
  «сошлось».
- Глубина истории — 2 года, окнами запроса по 7 дней.
- Автоимпорт работает **вперёд**: восстановить давнюю историю подробнее, чем отдаёт API,
  невозможно.
- **PnL % и плечо есть не у всякой сделки.** Обе величины берутся из `closed-pnl`
  биржи, и там, где сделка с ним не сопоставилась, стоит прочерк, а не ноль.
- **Разбор, написанный после результата, — это память под исход.** Дневник
  отвечает на вопрос «как разложить мою торговлю», но не на «были ли входы
  хороши»: последнее показал бы только стоп, записанный до входа.
